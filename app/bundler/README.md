# bundler

`bundler` 会把一个 package executable 及其可达的内部模块打包成单个
Haskell 源文件。

`bundler` bundles one package executable and its reachable internal modules
into a single Haskell source file.

```sh
cabal run bundler -- --exec luogu-wip -o bundled-luogu.hs
```

## 参数 / Options

- `--exec <name>` 选择要打包的 package executable。省略时使用 package
  描述中的第一个 executable stanza。
  Selects the package executable to bundle. When omitted, the first executable
  stanza in the package description is used.
- `-o, --output <path>` 选择生成的源文件路径。省略时输出到 stdout。
  Selects the generated source path. When omitted, output is written to stdout.
- `--package-dir <dir>` 选择包含 `.cabal` 文件的 package 目录，默认是当前目录。
  Selects the package directory containing the `.cabal` file. The default is
  the current directory.
- `--compact-names` 使用短 hash 生成名。默认输出会保留模块名和原始标识符，便于
  阅读和调试。
  Uses short hash-based generated names. By default, generated names keep the
  module and original occurrence visible for easier reading and debugging.

## 示例 / Examples

```sh
bundler --exec luogu-wip > /tmp/luogu.hs
cabal run bundler -- --exec codeforces-wip -o /tmp/codeforces.hs
ghc -fforce-recomp -fno-code /tmp/luogu.hs
ghc -fforce-recomp -fno-code /tmp/codeforces.hs
```

使用 `cabal run` 时建议显式传 `-o`，避免 Cabal 的构建日志和 bundler 的 stdout
输出混在一起。Use `-o` with `cabal run` so Cabal build logs do not mix with
bundler's stdout output.

## 实现说明 / Implementation Notes

MVP 依赖 Cabal 和 GHC 加载选中的 executable、发现可达模块、展开 CPP、在类型检查
期间运行 Template Haskell，并产出 renamed/typechecked module data。输出结果是
一个 `module Main (main) where` 源文件：内部模块会被拉平，内部名称会被改写成
确定性的生成名称，普通外部引用会通过 qualified imports 渲染。默认生成名称偏向
可读性；传 `--compact-names` 时会改用更短的 hash 名以进一步压缩输出。

The MVP relies on Cabal and GHC to load the selected executable, discover
reachable modules, expand CPP, run Template Haskell during typechecking, and
produce renamed/typechecked module data. The output is a `module Main (main)
where` source file with internal modules flattened, internal names rewritten to
deterministic generated names, and ordinary external references rendered through
qualified imports. Generated names are readable by default; pass
`--compact-names` to switch to shorter hash-based names for smaller output.

Core pruning 会在拉平后的候选 `Main` 模块上执行。Bundler 使用从 `main` 出发的
Core 可达性删除最终入口点不需要的声明组，同时保守保留无法安全映射的声明组，或被
保留 source group 依赖的声明组。

Core pruning is run on the flattened candidate `Main` module. The bundler uses
Core reachability from `main` to remove declaration groups that are not needed
by the final entry point, while conservatively retaining declaration groups that
cannot be mapped safely or that are required by retained source groups.

## 已知限制 / Known Limits

- 输出格式由 GHC pretty-printing 生成，不保留注释或原始排版。
  Output formatting is generated by GHC pretty-printing and does not preserve
  comments or original layout.
- `NoImplicitPrelude`、`RebindableSyntax`、大型 Template Haskell 展开等复杂
  extension 组合仍等待更多 fixture 覆盖。
  Complex extension combinations such as `NoImplicitPrelude`,
  `RebindableSyntax`, and large Template Haskell expansions are still staged
  behind additional fixtures.
- Bundler 不会把 Core 反编译回 Haskell；Core 只用于驱动源代码声明裁剪。
  The bundler does not decompile Core back into Haskell; Core only drives
  source declaration pruning.

## 常见失败模式 / Common Failure Modes

- 当 package 目录没有 `.cabal` 文件、存在多个 `.cabal` 文件，或 package 描述无法
  解析时，Cabal package 加载会失败。
  Cabal package loading fails when the package directory has no `.cabal` file,
  has multiple `.cabal` files, or the package description cannot be parsed.
- 未知 executable 名称会报错，并列出可用 executable。
  Unknown executable names fail with the available executable list.
- GHC load/typecheck/CPP/Template Haskell 失败会带上底层 GHC diagnostics。
  GHC load/typecheck/CPP/Template Haskell failures are reported with the
  underlying GHC diagnostics.
- 输出写入失败会包含目标路径和 I/O 错误。
  Output write failures include the target path and the I/O error.
